# Paper Research Hub 视觉设计系统

> **项目：** Paper Research Hub
> **状态：** 实施基线
> **日期：** 2026-07-16
> **适用范围：** 首页、论文目录与详情、趋势中心、研究机会、Topic/Method/Venue 专题页
> **设计目标：** 学术情报门户，高可发现、高密度、可扫描、证据可追溯

## 1. 文档契约

本文件是视觉与交互的唯一全局事实源。实现页面前必须先读取本文件，再读取
`design-system/paper-research-hub/pages/<page>.md`。

页面文件只能记录：

- 信息架构；
- 内容优先级；
- 页面独有但可复用的组合方式；
- 为该页面确有必要的响应式变化。

页面文件不得重新定义颜色、字体、圆角、阴影、图标、动效、焦点样式或品牌语气。
如页面文件与本文件冲突，以本文件为准；只有明确标注为“必要 override”的布局规则
可以覆盖对应的全局布局默认值。

当前系统只定义一套亮色主题。任何页面不得自行切换暗色、渐变主题或章节配色。
未来若增加暗色主题，必须在本文件中一次性定义完整 semantic token 映射，并对所有
组件和数据可视化重新完成 WCAG AA 审计。

## 2. 体验原则

1. **先发现，后判断。** 搜索、分类、筛选、榜单和专题入口持续可见，降低寻找成本。
2. **先结论，后证据。** 趋势与机会先给清晰摘要，再紧邻展示窗口、公式、覆盖率、
   来源和限制。
3. **高密度不等于拥挤。** 使用稳定网格、短标题、对齐数值、分组留白和渐进披露，
   不用更多颜色制造层级。
4. **事实与分析分层。** 论文元数据、来源断言、指标快照、模型分析和推荐状态必须有
   不同标签与来源说明。
5. **未知不是零。** 缺失、未覆盖、不可公开、证据不足和请求失败必须分别呈现，不用
   猜测值或静默占位替代。
6. **图形不能垄断信息。** 每张图必须有文本摘要和可访问的表格替代。
7. **稳定优先于炫技。** 无装饰性视差、滚动劫持、数字滚动、脉冲提示或图表入场表演。
8. **一个系统覆盖所有页面。** 首页、论文、趋势和机会共享同一 palette、组件语法和
   交互状态。

## 3. 设计语言

### 3.1 视觉性格

- **学术可信：** 清晰来源、克制用色、精确数字、长期可读。
- **情报工作台：** 搜索优先、筛选明确、榜单紧凑、状态可比较。
- **温和而非冷硬：** warm neutral 作为大面积背景，navy/teal 提供结构与信息，
  coral 只用于需要注意的决策和风险。
- **目录式高可发现性：** 借鉴成熟目录产品的搜索、场景入口、排行和评分结构，
  不复制其品牌色、营销语气、图标或装饰。

### 3.2 禁止项

- 不使用页面级 palette、章节渐变、彩虹色序列或单页暗色模式。
- 不使用 emoji 作为图标、状态或装饰。
- 不使用玻璃拟态、霓虹发光、强渐变按钮、重投影或浮夸 3D。
- 不使用没有数据含义的波纹、粒子、网格背景、仪表盘、环形进度或装饰曲线。
- 不以颜色作为唯一状态信号。
- 不为了“学术感”在密集 UI 中混用多套衬线字体。
- 不在卡片整体上默认添加点击手势；只有真实可导航或可操作区域可交互。

### 4.3 对比度基线

以下组合已按 WCAG 对比度算法核算；实现不得降低透明度后继续宣称满足同一组合。

| 前景 / 背景 | 对比度 | 允许用途 |
|---|---:|---|
| `--ink` / `--paper` | `15.45:1` | 全部文字 |
| `--navy-900` / `--paper` | `10.36:1` | 标题、链接、图标 |
| `--teal-700` / `--surface` | `6.62:1` | 链接、状态文字 |
| `--coral-700` / `--surface` | `5.93:1` | 错误、风险文字 |
| `--coral-700` / `--coral-100` | `4.62:1` | 负向状态胶囊 |
| `--ochre-700` / `--ochre-100` | `5.71:1` | 谨慎状态胶囊 |
| `--warm-600` / `--paper` | `5.87:1` | 次级正文 |
| 白色 / `--navy-900` | `10.93:1` 以上 | 主按钮、深色导航 |

规则：

- 普通文字至少 `4.5:1`，大字至少 `3:1`。
- 数据线、焦点环、输入边界和关键图标与相邻背景至少 `3:1`。
- `--color-border` 只用于非必要分隔；可操作控件必须使用
  `--color-border-control` 或更强边界。
- 禁止把文字或数据线 opacity 降到无法满足目标对比度。

### 4.4 字体

```css
--font-ui:
  "Inter",
  "Noto Sans SC",
  "Source Han Sans SC",
  "PingFang SC",
  "Microsoft YaHei",
  system-ui,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  sans-serif;

--font-data:
  "Roboto Mono",
  "SFMono-Regular",
  Consolas,
  "Liberation Mono",
  monospace;
```

字体策略：

- 全站标题、正文、导航和表单统一使用 `--font-ui`。
- 英文优先使用 Inter，简体中文优先使用 Noto Sans SC 或本地高质量中文系统字体。
- `--font-data` 只用于 DOI、标识符、公式版本、窄列数字和代码，不用于长段正文。
- 数值、排名、百分比和日期使用 `font-variant-numeric: tabular-nums`。
- 页面不得引入独立字体组合。
- Web 字体加载使用 `font-display: swap`，并保留指标相近的系统 fallback。

### 4.7 圆角、边框与阴影

| Token | 值 | 用途 |
|---|---:|---|
| `--radius-sm` | `4px` | 标签、数据单元 |
| `--radius-md` | `8px` | 输入、按钮、卡片 |
| `--radius-lg` | `12px` | 大面板、抽屉 |
| `--radius-xl` | `16px` | 模态框；谨慎使用 |
| `--shadow-1` | `0 1px 2px rgb(16 42 67 / 0.06)` | sticky header、轻微分层 |
| `--shadow-2` | `0 12px 32px rgb(16 42 67 / 0.14)` | popover、drawer、modal |

规则：

- 卡片默认以边框区分，不默认悬浮。
- hover 不改变卡片尺寸、位置或阴影层级；只调整边框、背景或文字颜色。
- 阴影只表示真实层级，不用于装饰。
- pill 圆角只用于状态、标签和短筛选条件，不用于所有按钮和卡片。

### 4.8 图标

- 只使用一套 Lucide 风格 SVG 线性图标，默认 `20px`、`1.75px` stroke。
- 常用尺寸：`16px` 辅助、`20px` 默认、`24px` 主导航。
- 图标与文字共同出现时，文字承担主要语义。
- icon-only 控件必须有可访问名称、tooltip 和 `44 × 44px` 命中区域。
- 不使用 emoji、位图图标、品牌仿制图标或混合填充/描边语言。

### 4.9 动效

| Token | 值 | 用途 |
|---|---:|---|
| `--duration-fast` | `120ms` | pressed、focus 可视变化 |
| `--duration-base` | `180ms` | hover、展开、popover |
| `--duration-slow` | `240ms` | drawer、modal |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 默认进入与状态变化 |

动效规则：

- 只动画 `opacity` 和 `transform`；不得动画布局尺寸制造抖动。
- 路由切换不加全页淡入淡出，避免阻塞扫描和浏览器历史操作。
- 图表默认直接呈现，不做逐线绘制、数字滚动、脉冲异常点或持续闪烁。
- 数据更新以短暂背景强调和文本时间戳提示，持续不超过 `180ms`。
- `prefers-reduced-motion: reduce` 时将非必要动画与平滑滚动全部关闭；
  skeleton 不使用 shimmer。

## 5. 全局布局

### 5.1 App Shell

- 顶部使用固定高度、sticky 的全局 header，包含品牌名称、全局搜索入口、一级导航和
  数据更新时间入口。
- 一级导航固定为：首页、论文、趋势、研究机会。Topic、Method、Venue 通过搜索、
  筛选、专题入口和面包屑发现，不挤入一级导航。
- `1024px` 及以上使用左侧 discovery rail，承载快捷筛选、热门 Topic/Method、
  精选策略入口和保存视图；它是导航补充，不重复一级导航。
- `1440px` 可增加右侧 contextual aside，用于证据、公式或来源详情。若没有上下文内容，
  主内容扩展占用空间，不保留空栏。
- header、rail 和 aside 都不得形成独立的嵌套主滚动区。

### 5.2 容器与网格

| 视口 | 页面 gutter | 内容结构 |
|---|---:|---|
| `375px` | `16px` | 单列；筛选进入 drawer |
| `768px` | `24px` | 8 列；主内容单列或 `5 + 3` |
| `1024px` | `28px` | 左 rail `216px` + 主内容 |
| `1440px` | `32px` | 左 rail `232px` + 主内容 + 可选 `300px` aside |

- shell 最大内容宽度 `1360px`，居中放置。
- 主数据网格使用 12 列；卡片最小可读宽度 `280px`。
- 页面不能产生横向滚动。宽表在移动端转换为卡片或定义清晰的行详情。
- 仅在无法转换且确有比较价值的桌面表格中，允许带可见说明的局部横向滚动容器；
  页面主体仍不得溢出。
- sticky 工具栏必须为其占用空间预留 offset，不遮挡锚点、标题或最后一行内容。

### 5.3 页面层级

每个页面按相同顺序组织：

1. 面包屑或位置说明；
2. `h1`、一句任务描述、更新时间/覆盖率；
3. 主要搜索、窗口或状态控制；
4. 当前筛选摘要；
5. 核心内容；
6. 方法、来源和限制；
7. 相关专题或下一步。

首页可以省略面包屑，但不得省略更新时间和数据范围。

## 6. 核心组件

### 6.1 Global Header

- 高度：移动端 `64px`，桌面 `72px`。
- 品牌区域只显示文字标识和简洁 SVG mark，不使用营销口号占据首屏。
- 当前导航使用字重、下边标记和 `aria-current="page"`，不只改变颜色。
- 搜索入口在全部视口可见。移动端可显示为图标加“搜索”文本，不得仅保留放大镜。
- 菜单打开后锁定背景滚动，`Escape` 关闭，关闭后焦点返回触发器。

### 6.2 Command Search

- 全局搜索是首要发现入口，支持论文标题、作者、Topic、Method、Dataset、Benchmark、
  Venue 和标识符。
- 输入必须有可见 label；placeholder 只提供示例。
- 建议项按实体类型分组，每项展示名称、类型和一条区分信息。
- 键盘支持上下键、Enter、Escape，并正确实现 combobox/listbox 语义。
- 空建议、网络失败和无匹配分别呈现。
- 搜索提交进入可分享 URL；浏览器前进/后退恢复查询与筛选。

### 6.3 Buttons 与 Links

**Primary button**

- navy 背景、白色文字、`8px` 圆角、最小高度 `44px`。
- 每个视图同一层级最多一个 primary action。

**Secondary button**

- surface 背景、`--color-border-control` 边框、navy 文字。

**Tertiary button**

- 透明背景、teal 文字；用于低优先操作。

**Destructive button**

- 仅用于真实破坏性操作，不用于“当前不建议做”等数据状态。

**Text link**

- teal 文字，hover 出现下划线；正文链接默认带下划线。

所有控件必须定义 default、hover、pressed、focus-visible、disabled 和 loading。
disabled 使用原生语义并停止交互，不只降低透明度。

### 6.4 Search 与 Filter Controls

- 桌面使用紧凑 filter bar 或左 rail；移动端使用“筛选”按钮打开 drawer。
- 当前筛选使用可移除 chips，并提供“清除全部”。
- 多选筛选使用 checkbox 语义；互斥视图使用 radio 或 segmented control。
- 精选/全部、7/30/90 天等 segmented control 必须有可见组标签。
- 数量、排序、快照时间和覆盖率保持在结果工具栏中，避免用户误解当前集合。
- 筛选变化只更新相关结果，不丢失滚动位置和已选择的视图。

### 6.5 Paper Card

固定信息顺序：

1. 论文状态与来源类型；
2. 完整标题；
3. 作者、Venue、发布日期；
4. 一至两行摘要或关键发现；
5. Topic、Method、Dataset、Benchmark 标签；
6. 精选策略、JIF/JCR 年份、PubMed/PMC、代码等证据；
7. 引用趋势、代码增长或相关性等可解释指标；
8. 查看详情。

规则：

- 整卡可点击时仍保留显式详情链接，并避免内部交互嵌套。
- DOI、PMID、PMCID、arXiv ID 等放在详情或可展开元数据区，不压过标题。
- 元数据来源未知时显示“未覆盖”，不得显示假定的否定状态。
- 撤稿、撤回、拒稿、被替代或当前排除状态使用文本标签和 coral 左边标识，
  并说明其不会进入推荐榜。

### 6.6 Ranking Table

- 默认按核心指标降序，列头说明指标与窗口。
- 第一列为稳定排名；排名变化同时显示方向词、数值和图标，不只用颜色。
- 表头 sticky 仅限页面主滚动；不得创建嵌套纵向滚动。
- 可排序列使用按钮和 `aria-sort`。
- 每行至少包含名称、核心值、变化、证据量和更新时间。
- `375px` 转换为排名卡片；`768px` 可隐藏低优先列并通过行详情展开；
  `1024px` 以上呈现完整表格。

### 6.7 Metric Card

- 一张卡只回答一个问题。
- 顺序为：指标名、值、变化、窗口、覆盖率、解释入口。
- 大数字不超过 `--text-3xl`，避免数字墙压过论文与证据。
- 没有基线时显示“缺少基线”，不显示 `0%`。
- sparklines 只作辅助，必须同时显示文本变化和可访问摘要。

### 6.8 Trend Panel

包含：

- 标题和实体范围；
- 7/30/90 天窗口或明确时间粒度；
- 一句关键结论；
- 图表；
- 图例与系列开关；
- 生成时间、覆盖率、公式版本；
- “查看数据表”切换；
- 数据不足、加载、错误状态。

单图最多四条主要系列；超过四条改为排行表、small multiples 或让用户主动选择。

### 6.9 Evidence Bar

用于展示增长、竞争密度、数据可得性、可复现性、覆盖率等确定性信号。

- 每行包含标签、可见数值、区间含义和来源/缺失说明。
- track 使用 warm neutral，fill 使用 semantic color；文字和刻度承担主要语义。
- “缺失”使用空心边框与“缺失”文本，不以零长度实心条表示。
- 阈值 marker 必须带数值或标签。
- 多条证据按同一量纲对齐；不同量纲不得伪装成可直接比较。

### 6.10 Opportunity Matrix

- 横轴默认表示竞争密度，纵轴默认表示增长信号。
- 状态以形状、描边和文本共同编码：
  - 值得做：实心圆 + “值得做”；
  - 谨慎做：菱形 + “谨慎做”；
  - 当前不建议做：方形 + “当前不建议做”；
  - 证据不足：空心圆 + “证据不足”。
- coral 只用于“当前不建议做”和明确风险；“证据不足”保持中性虚线，不归入负向。
- 点大小不得编码关键变量，避免难以比较和触控。
- 选择一个点后，紧邻显示公式版本、窗口、覆盖率、四类 evidence bars、
  证据论文、限制和缺失信号。
- 矩阵只是发现入口，不替代正式推荐公式，也不能只凭象限生成结论。
- `375px` 默认用按状态分组的机会卡片和排序表；矩阵作为可选概览。

### 6.11 Status Badge 与 Tag

- 状态 badge 使用浅底、深色文字、图标或形状标记。
- 标签用于 Topic/Method 等分类，不与状态 badge 混用。
- 精选策略 badge 必须显示规则与年份，例如“JCR Q1 · 指标年”或
  “JIF ≥ 10 · 指标年”，不可只写“精选”。
- “PubMed 收录”“PMC 开放全文”“出版社元数据”分别表达，不能暗示元数据等于可复用全文。
- badge 文本不得依赖 tooltip 才能理解。

### 6.12 Source Provenance

- 来源面板按“规范事实、来源断言、指标快照、分析结果”分组。
- 展示来源名、字段、抓取/生成时间、内容或版本标识、许可状态和冲突说明。
- 来源冲突不静默合并；并列展示并标出当前采用规则。
- 许可证与全文可用性用文字陈述，不用单一锁图标。

### 6.13 Drawer、Popover、Modal 与 Tooltip

- filter 使用 drawer，短菜单使用 popover，阻断型确认才使用 modal。
- modal 打开时将焦点移入并形成焦点环，关闭后恢复到触发器。
- `Escape` 可关闭非破坏性浮层；破坏性确认仍必须有明确取消按钮。
- tooltip 只补充解释，不承载完成任务所需的唯一内容；键盘 focus 同样可触发。
- 浮层不使用 blur 作为装饰，仅使用清晰 scrim 与 `--shadow-2`。

## 7. 组件状态

### 7.1 交互状态

| 状态 | 视觉与行为 |
|---|---|
| Default | 清晰边界、稳定布局 |
| Hover | 背景或边框轻微变化；不位移、不缩放 |
| Pressed | `120ms` 内加深背景或降低明度 |
| Focus visible | `3px` teal ring + `2px` surface offset |
| Selected | 图标/形状、字重和边界共同表达 |
| Disabled | 原生 disabled、不可聚焦、文字说明原因（需要时） |
| Loading | 保留尺寸，按钮显示短文本或 spinner，防止重复提交 |

### 7.2 数据状态

**Loading**

- `300ms` 内不闪现 placeholder；超过后使用保留最终几何的 skeleton。
- skeleton 不模拟无法预知的大段内容，不使用 shimmer。
- 保留页面标题和当前筛选，避免用户失去上下文。

**Empty**

- 说明是“当前筛选无结果”“数据尚未生成”还是“来源未覆盖”。
- 提供与原因匹配的下一步，例如清除筛选、切换窗口或查看方法说明。
- 插图只能辅助，不承担关键信息。

**Error**

- 在失败区域内显示错误摘要、可执行的重试、请求 ID 或问题详情入口。
- 局部失败不伪装为空结果；全页失败仍保留导航和页面任务说明。

**Stale**

- 显示快照生成时间和“数据较旧”文字，不用闪烁警报。
- 允许查看旧快照，但不得隐去其窗口与版本。

**Insufficient evidence**

- 使用独立中性状态，列出缺失信号和最低证据要求。
- 不提升为正向或负向建议，不套用 coral 风险样式。

**Restricted or unavailable**

- 区分受限全文、无公开全文、元数据未覆盖和外部链接失败。
- 不生成替代下载链接或含糊的“可用”标签。

## 8. 数据可视化

### 8.1 通用规则

每个图表必须具备：

1. 描述性标题；
2. 时间窗口与粒度；
3. 单位和坐标轴标签；
4. 可见图例或直接标注；
5. 一句文本结论；
6. 数据覆盖率与生成时间；
7. 公式或计算说明入口；
8. 可切换的数据表；
9. 空、加载、错误和证据不足状态；
10. 无颜色条件下仍可区分的线型、形状或文字。

### 8.2 图表颜色

固定系列顺序：

1. `--teal-600`，实线；
2. `--navy-800`，长虚线；
3. `--coral-600`，点划线，仅用于风险、下降或明确对照；
4. `--ochre-700`，点线，用于谨慎或基线。

gridline 使用 warm neutral，数据线与背景至少 `3:1`。不得为每个 Topic 自动分配随机色。

### 8.3 图表类型

- 时间变化：折线图；预测与实测必须使用不同线型和明确标签。
- 排名比较：横向条形图或排名表；超过 15 项优先表格。
- 多指标对比：small multiples 或 bullet-style evidence bars。
- 机会发现：二维矩阵加相邻证据面板。
- 类别占比：优先排序条形图或表格，不使用饼图、环图。
- 精确值优先的场景：直接使用表格。

### 8.4 禁止的 chart junk

- 3D、透视、阴影柱、拟物仪表盘；
- 面积渐变、霓虹发光、背景纹理；
- 平滑到改变数据含义的曲线；
- 双 Y 轴但无强制解释；
- 自动播放、无限循环、点位脉冲；
- 与结论无关的插画、图标或背景网格；
- 仅 hover 才能读取的关键值。

### 8.5 表格与文本替代

- “查看数据表”是图表组件的固定可见操作，不藏在 overflow menu。
- 数据表包含图表中使用的全部时间点、系列、单位与缺失值。
- 缺失值使用“缺失/未覆盖”，不用空字符串或零。
- 表格列可排序时使用 `aria-sort`；大量数据提供分页或下载，不在 DOM 中堆积。
- 图表容器提供简短 screen-reader summary，说明主要变化和异常。

## 9. 响应式行为

### 9.1 `375px`

- 单列内容，header 保留品牌、搜索和菜单。
- 一级导航进入菜单，但当前页面名称持续可见。
- 筛选、证据和来源进入 drawer；当前筛选 chips 留在主内容。
- 论文与排行转换为卡片，标题完整优先，次级字段可展开。
- 图表最多显示两条默认系列，减少刻度但不删单位；数据表纵向展开。
- 机会页默认列表优先，矩阵为可选视图。
- 不使用固定底部 CTA；保证浏览器缩放和系统手势空间。

### 9.2 `768px`

- 使用 8 列网格；多数页面保持主内容单列。
- 首页可使用 `5 + 3` 组合展示主榜单与次级摘要。
- filter drawer 仍为默认，常用窗口和排序可直接显示。
- 表格显示核心列，低优先字段进入行详情。
- 证据面板可与内容并列，但不得缩窄正文到不可读。

### 9.3 `1024px`

- 显示 `216px` discovery rail。
- 主内容使用 12 列网格，趋势与榜单可并列。
- 完整 filter bar 与主要表格列可见。
- contextual evidence 默认位于主内容下方或临时 drawer，不强制第三栏。

### 9.4 `1440px`

- shell 最大宽度 `1360px`，左 rail `232px`。
- 需要持续对照证据的页面可使用 `300px` contextual aside。
- 首页最多三列卡片；趋势图最多两列，不用四列迷你图制造噪声。
- 长段方法说明仍限制 `68ch`，不随屏幕无限拉宽。

### 9.5 缩放与重排

- 支持浏览器 `200%` 文字缩放和 `400%` 页面缩放。
- 在约 `320 CSS px` 宽度下仍可完成搜索、筛选、查看证据和返回。
- 不禁用 pinch zoom，不依赖 hover 完成任务。
- 中英文长标题、作者列表和 Venue 名称必须允许换行。

## 10. Accessibility

### 10.1 结构

- 页面必须包含 skip link、`header`、`nav`、`main`、必要的 `aside` 和 `footer`。
- 每页只有一个明确 `h1`，区块标题顺序连续。
- 路由切换后将焦点移到 `main` 或页面 `h1`，并恢复合理滚动位置。
- 面包屑使用 `nav` 与可访问名称，当前项使用 `aria-current="page"`。

### 10.2 键盘

- 所有功能可通过键盘完成，Tab 顺序与视觉顺序一致。
- 自定义 tabs、combobox、menu 和 dialog 遵循对应 ARIA pattern。
- 不设置正数 `tabindex`，不建立键盘陷阱。
- drawer、modal 和 popover 支持 `Escape`，关闭后恢复焦点。
- 图表交互必须有相同能力的按钮、筛选器或数据表替代。

### 10.3 焦点

```css
:focus-visible {
  outline: 3px solid var(--color-focus);
  outline-offset: 2px;
}
```

- 不使用 `outline: none`。
- 深色按钮上的焦点环增加白色内/外 offset，保证边界可见。
- sticky 区域不得遮挡被聚焦元素；使用 `scroll-margin-top`。

### 10.4 屏幕阅读器与动态内容

- 图标按钮、图表、趋势摘要和状态变化必须有清晰可访问名称。
- 排序、分页、筛选结果数和异步状态使用适当 live region；不得抢夺焦点。
- toast 使用 `aria-live="polite"`，错误摘要使用 `role="alert"` 或 assertive live region。
- 纯装饰 SVG 使用 `aria-hidden="true"`；有意义图形提供标题或文本替代。
- 中英文内容使用正确页面 `lang`，必要时对局部外语标题标注 `lang`。

### 10.5 表单

- 每个输入有可见 label、helper text 和相邻错误信息。
- 错误说明包含原因和修复方法；多错误表单提供顶部错误摘要及锚点。
- 校验在 blur 或提交后发生，不在每次键入时打断用户。
- 提交失败后聚焦第一个错误字段；长表单保留用户输入。

### 10.6 Reduced Motion

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

实现不得依赖动画结束触发核心状态。

## 11. 内容与文案

- 使用“最新论文”“热门 Topic”“方法采用率”“研究机会”等任务型标题。
- 避免“革命性”“爆炸增长”“必做”“赢家”等营销判断。
- 推荐状态必须同时显示“基于什么、何时生成、覆盖多少、有什么限制”。
- 时间使用明确日期或窗口，不单独写“今天”“最近”。
- 数值保留合理精度；百分比通常一位小数，排名和样本量使用整数。
- 中文主界面中的英文实体名保持原名，不进行不可靠翻译。
- 未知状态使用“未覆盖”“缺少基线”“证据不足”等精确表述。

## 12. 实施验收

### 12.1 全局一致性

- [ ] 所有页面只使用本文件 semantic color tokens。
- [ ] 没有页面级 palette、单页暗色模式或独立字体。
- [ ] navy、teal、coral 和 warm neutral 的角色保持一致。
- [ ] 图标只来自同一 SVG 图标语言，没有 emoji 图标。
- [ ] 卡片、按钮、输入、badge、表格和浮层状态一致。

### 12.2 信息密度与发现

- [ ] 搜索、一级导航、筛选摘要和更新时间在全部视口可发现。
- [ ] 论文、Topic、Method、Venue 和机会之间有明确可分享链接。
- [ ] 关键榜单、趋势和机会可在两次主要交互内到达。
- [ ] 高密度内容通过分组、对齐和渐进披露扫描，不靠缩小字号。

### 12.3 数据与证据

- [ ] 趋势展示窗口、粒度、覆盖率、公式版本和生成时间。
- [ ] 机会展示 status、证据论文、四类信号、限制和缺失信号。
- [ ] 精选状态展示具体规则、指标年份和来源。
- [ ] 未知、空、错误、受限、过期和证据不足互不混淆。
- [ ] 所有图表有文本摘要和完整数据表替代。

### 12.4 Accessibility

- [ ] 普通文字达到 `4.5:1`，关键非文本 UI 达到 `3:1`。
- [ ] 375、768、1024、1440 均无页面横向溢出。
- [ ] 键盘可完成导航、搜索、筛选、排序、分页和证据查看。
- [ ] 焦点始终可见，路由和浮层焦点管理正确。
- [ ] `prefers-reduced-motion` 下没有非必要动画或 shimmer。
- [ ] `200%` 文字缩放和 `400%` 页面缩放仍可完成核心流程。

### 12.5 禁止项复核

- [ ] 没有 chart junk、3D、仪表盘、装饰渐变或随机彩色系列。
- [ ] 没有 hover-only 信息、颜色唯一编码或低对比辅助文字。
- [ ] 没有假数据、静默 fallback、把缺失值当零或把元数据当全文。
- [ ] 没有为了视觉差异重新定义页面品牌。
